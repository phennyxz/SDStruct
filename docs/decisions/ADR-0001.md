# ADR-0001 — Biblioteca Bash com modelo canônico compartilhado

- **Status:** aprovado conceitualmente
- **Data:** 2026-11-05
- **Decisores:** direção do projeto SDStruct

## Contexto

O projeto anterior possuía diferentes representações de estruturas de dados em Bash. A evolução para SDStruct exige preservar interfaces distintas sem manter motores semânticos independentes.

Também foi considerada a possibilidade de suportar desde o início várias linguagens e shells, mas isso ampliaria a complexidade antes de validar o núcleo.

## Decisão

1. O produto inicial será uma biblioteca Bash.
2. A versão mínima alvo será Bash 4.3.
3. As diferentes interfaces de armazenamento deverão compartilhar um modelo canônico.
4. O primeiro componente executável planejado será `takarr.sh`, um parser/conversor, não um motor de armazenamento.
5. JSON será o primeiro formato de entrada/saída planejado.
6. A sintaxe Vector será especificada separadamente antes de ser considerada estável.
7. Adaptadores para outras linguagens e compatibilidade POSIX/Dash ficam fora da primeira fase.

## Consequências

- Podemos utilizar recursos Bash adequados, incluindo arrays associativos e namerefs.
- Não precisamos simular limitações de outras linguagens no núcleo.
- Os contratos de conversão precisarão explicitar diferenças entre formatos.
- A representação canônica e a semântica dos dados precisam ser definidas antes de sua implementação definitiva.

## Decisões ainda não cobertas

Este ADR não aprova os códigos de tipo, separadores, escaping, formato físico dos registros, tratamento de posições não preenchidas, assinaturas da API ou licença.
